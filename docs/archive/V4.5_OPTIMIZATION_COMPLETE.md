## 💡 Key Insights

### Why Session Pooling Matters
TCP connections are expensive:
- **3-way handshake**: 50-100ms per connection
- **SSL handshake**: 100-200ms additional
- **Connection overhead**: 200+ ms per new connection

Session pooling reuses connections:
- **First request**: 200ms (handshake) + 100ms (data) = 300ms
- **Subsequent**: 0ms (reuse) + 100ms (data) = 100ms
- **Savings**: 200ms per request × 100 requests = 20,000ms = 20 seconds saved!

### Why Thread-Safety Matters
Without proper locking:
- Race conditions in cache operations
- Session corruption under concurrent load
- Unpredictable crashes and hangs

With proper locking:
- Atomic operations via `threading.Lock()`
- Double-check pattern reduces lock contention
- Predictable, stable performance

### Why Cleanup Matters
Without proper cleanup:
- Zombie connections persist after addon disable
- Memory leaks grow over time
- Resource exhaustion leads to crashes

With proper cleanup:
- All sessions closed on shutdown
- Memory freed immediately
- System resources stay healthy

## 🎓 Performance Optimization Principles Applied

1. **Reuse > Create**
   - Reuse sessions instead of creating new ones
   - Connection keep-alive instead of reconnects

2. **Consolidate > Duplicate**
   - Global session manager vs 15 separate managers
   - Shared connection pools vs separate pools

3. **Cache > Compute**
   - Cache keywords (24-hour TTL) vs re-call AI
   - Cache images (120-min TTL) vs re-search

4. **Order > Brute Force**
   - Request best performers first vs random
   - Skip blocked providers vs retry failures

5. **Timeout > Hang**
   - Per-provider optimal timeouts vs generic timeouts
   - Global timeout vs infinite waits

6. **Lock > Crash**
   - Double-check locking pattern vs race conditions
   - Atomic operations vs data corruption
